这个面板和你的手动流水线是什么关系

  • 三层配置：工作区 config.yaml（你的基准，面板只读）→ 面板覆盖 .uartix/yolo/config.json（只存与基准不同的键，改回默认时 diff 自己消失）→ 每次实验的完整快照 train_runs/<实验>-<时间>.yaml。
  • 面板能点的，命令行也跑得起来：训练页的「先看这次会用什么参数」和实验页的「等价命令」给的就是同一份 yaml 的三个入口——插件 runner（吃全部参数）、你自己的 scripts/train.py（只认它那 20 个键）、ultralytics CLI（吃引擎写的 args.yaml）。
  • 它不改你的东西：config.yaml、scripts/*.py、00~07*.bat、README_使用说明.txt 全程只读；这条不是承诺，是测试（逐文件比 mtime 与内容）。新参数走插件自带的 runner/，所以不需要动你的脚本。
  • 写只在这几处：.uartix/、annotations/、datasets/、runs/、logs/、models/、train_runs/——就是批准卡上列的那几枚，内核级牢笼，越界直接 ERR_ACCESS_DENIED。

模型、任务与数据

  • 只做 YOLO11 与 YOLO26：它们是同一个 ultralytics 包里的两代模型，不是两套环境，所以没有"切环境"这一说，只有"这次用哪一枚权重"。
  • 老数据不用重标：YOLO 文本标注格式（images/ + labels/ + data.yaml，归一化 class cx cy w h）在这两代之间通用。这是"我手上的老标注还能不能用"的答案。
  • 标注你自己来：面板不生成、不搬运、不改名、不删任何标注。它只登记一个投料口 annotations/（一个子目录 = 一批），素材夹留空时「构建数据集」直接从这个目录取。
  • 任务识别只是建议：判据是标签每行的 token 数（5 = 框，1+2N = 多边形）。点了「按建议设置」才会写进配置。9 个 token 时多边形与 OBB 分不开，面板只报出来不替你决定；混合标注按 detect 训会静默丢弃 segments。
  • 权重与任务不搭会当场拦：拿 detect 权重跑 segment，引擎会拒；面板在开跑前就说清楚，并且不留下半份快照。

参数面与几个版本坑

  • 参数表不是抄的：每一项都来自当前这套 ultralytics 的默认表（本机 111 键）。包里没这个键就不出现——所以键改名会自动跟上，不会出现"面板能填、引擎不认"。读不到时降级成最小集并明说。
  • 没有 half 这个开关：它在 8.4 已被 quantize 取代（导出页有这一项）。旧教程里那行打开半精度的写法在面板里找不到，不是漏了，是引擎不要了。
  • 续训只认 last.pt：best.pt 没有优化器/轮次状态，给它会静默退化；填 true 会让引擎去当前目录猜一个，所以面板要求你填完整路径。跨 ultralytics 版本续训一律不做（官方没有任何保证）。
  • 数字 / 文字类任务：fliplr / flipud 保持 0（镜像后字就反了），erasing、perspective 慎用。这两项面板会标红提醒。
  • 这台机器：16G 内存 → workers 保持 0；8G 显存 → batch 可以填 -1 让引擎自己挑，或 OOM 后减半。

为什么这次要重新批准

0.3.0 的清单多了两枚写目录（train_runs/ 与 annotations/），版本号也变了 ⇒ 信任指纹变化 ⇒ 会重新弹一次批准卡。这是设计的一部分，不是麻烦：装、启用、发布这三件事永远由你点， 面板和 AI 都不替你按。发布到市场是外发行为（源码出去了收不回来），所以那条路只到「打开页面」为止。
