# 插件市场：怎么上架一支插件

> 这里是**货架的源码**：作者交的元数据 + 包源文件。生成器把它们编译成 `public/market/index.json`，
> 应用每次打开市场页**实时读那份索引**（不内置快照兜底——过期答案不是降级，是错误）。
> 参照物：市场 App 是 `dsh-market/dsh-market`，清单是 `awesome-dsh-plugin`（一插件一文件、人工 PR、CI 生成索引）。
> **我们抄的是这套机制，不是它的包格式**——dsh 的插件是 npm 上的 JS 模块，我们的插件是 `uartix-plugin` 声明式包。

## 现在能走到哪一步（先说清，别按将来的功能读这份文档）

| | 状态 |
| --- | --- |
| 浏览货架、看详情、收藏 | **已可用**（标题栏那颗拼图图标 → 插件管理 → 「插件市场」；AI 助手的插件库面板里也有同一颗）|
| 点一下就把包装进本机 | **已可用**（N4）：卡片与详情各一颗按钮，装完是**停用态**，还要去插件库启用才生效；覆盖本机已有版本的那种会停在右下角的确认卡上等你点「装入」。离线那条路仍然在：把 `market/pkg/**` 编译出来的 `.uartix.json` 拷出来走 设置 → 插件管理 → 导入 |
| 预览图 | **已可用**（N3）：卡片首图 + 详情轮播 + 大图。**不放 SVG**（脚本容器），单边 8192 / 总像素 2500 万以内才显示；作者没给就照实说没给，不留空图位 |
| 改索引地址 / 镜像前缀 | **已可用**（N6 起在设置页，**P102 起搬进市场页顶上那颗齿轮**）：展开就是那两行。旁边会当场告诉你**这一条会不会被用上、不会的话为什么**（域不在放行清单＝会被拒；镜像前缀不合规＝按不用镜像继续）。默认仍是应用自带的示例货架（同源、不出网） |
| AI 能不能读货架 | **已可用**（N6）：自省目录多了 `market.status` / `market.entries` 两支**只读**视图。它们**一次网都不联**——没取过就照实说没取过，不会替你打开市场页 |
| 提名让 AI 装一支 | **已可用**（C2）：`propose_market_install` 只把"会装成什么"讲给你听（它会下载并按索引校验），**不装、不暂存、不启用**；每次都要你在批准卡上点一次，落地仍然是你在市场页那颗「装入」或终端里的 `uartix plugin install` |
| 字节放在 npm 上 | **已可用**（R2）：条目多一节 `npm`，`packageUrl` 就是官方 registry 的 tarball。索引仍是唯一的门——哈希与字节数算的是**那枚 tarball**，取回来只从里面读那一枚清单，**不装依赖、不跑包内任何脚本** |

## 交两样东西，跑一条命令

1. **包源**，二选一：
   - `market/pkg/<名字>.uartix.json` —— 成品包，字节原样上架（**设置 → 插件管理 → 导出** 出来的就是这个形状，多数时候你不用手写）；
   - `market/pkg/<名字>/manifest.json` ＋旁挂真实文件 —— 适合要写 HTML/CSS 的小部件与面板：
     产物里把内联字段改成 `<字段>File` 指向同目录的文件，生成器负责读进来。

   ```json
   {
     "artifacts": {
       "rig.json": { "kind": "widget", "format": "html", "htmlFile": "rig.html" }
     }
   }
   ```
   `rig.html` 就是普通 HTML（可以换行、可以写 `"`），编译后上架包里是 `"html": "<div>…</div>"`。
   **投稿文件是严格 JSON：不能带注释**（本仓库文档里的注释只是说明，别照抄）。
2. **元数据**：`market/entries/<名字>.json` —— 只写货架要显示的东西，**不写哈希和字节数**。字段见下面《元数据字段》。

投稿前自检那一条命令（**离线**：不用开着应用、不联网、不读设置）：

```sh
npm run build:plugin-cli        # 只需要一次；产出 dist-cli/uartix-plugin.cjs
node dist-cli/uartix-plugin.cjs validate market/pkg/<名字>.uartix.json
# 仓库里也可以直接：npm run market:validate -- market/pkg/<名字>
```

它跑的就是**上架会跑的那几道**：源包内联 → `validateManifest`（生产校验器，与 AI 存插件、
导入文件包同一个）→ 元数据与包体对账 → 索引契约 `parseEntry`。回执会列出跑了哪几道、用的哪一版校验器，
跳过的也照实说（比如只给了包、没给那份 entries）。退出码 0 通过 / 1 不通过。
`dist-cli/uartix-plugin.cjs` 是单文件，拷到哪儿都能跑——但**别把它当成"另一套更松的检查"**：
它就是同一批校验器，所以本地绿了上架就不会红。

生成与全量核对（维护者 / CI 用）：

```sh
npm run market:gen      # 编译源包 → 算 sha256 与字节数 → 对账 → 写 public/market/index.json
npm run test -- market  # 货架内容测试：包过生产校验器 / 索引与包一致 / 解析零丢弃 / 无孤儿源
```

## 元数据字段（`market/entries/*.json`）

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` `name` `author` `category` | 是 | `id` 小写点分；`category` 必须是 `market/categories.json` 里的键 |
| `description` | 是 | `{ zh, en? }`，`zh` 必填、`en` 可选（缺了就只显一种，界面不替你补）|
| `version` `minAppVersion` `updated` | 是 | 前两个必须与包里一致；`updated` 为 `YYYY-MM-DD` |
| `packageFile` | 是 | `"<名字>.uartix.json"` 或 `"<名字>/"`（目录源）|
| `publicUrl` | 是 | 同源地址**末段必须等于实际产物名**：目录源 `rig/` ⇒ `/market/pkg/rig.uartix.json`（不一致就构建失败，别留到装机 404）|
| `capabilities` | 是 | 与包里逐字一致；多一项少一项都构建失败 |
| `screenshots` | 否 | 最多 8 张；同源文件必须真实存在 |
| `homepage` / `discussion` / `changelogUrl` | 否 | 只收 https 且域在白名单内（白名单只有一份，见文末——别抄进这份表里，抄了就等着过期）|
| `npm` | 否 | 有这一节＝字节来自 npm：`{ name, version, pack }`。`version` 必须等于条目 `version`；`pack` 是你 `npm pack` 出来的那枚 `.tgz`（放进 `market/pkg/`，哈希与字节数按它算）；`publicUrl` 必须是官方 registry 拼出来的那个地址 |

## 另一种投稿：字节放在 npm 上（R2）

作者侧多做的只有两件事——`npm publish`，然后把 pack 出来的 `.tgz` 一并交进来：

1. **npm 包根放一枚 `uartix-plugin.json`**，它就是货架上那枚包：**产物要内联**（`artifacts` 里带正文，不要指望我们去看 `package/artifacts/*.html` —— 我们只读那一枚清单，别的成员一概不碰）；`id`/`version` 必须与 `market/entries/<名字>.json` 逐字一致。
2. 元数据多一节，并把 `publicUrl` 填成 registry 的地址：

   ```json
   {
     "version": "1.0.0",
     "packageFile": "probe/manifest.json",
     "publicUrl": "https://registry.npmjs.org/probe/-/probe-1.0.0.tgz",
     "npm": { "name": "probe", "version": "1.0.0", "pack": "probe-1.0.0.tgz" }
   }
   ```

   - `packageFile` 仍要交（生成器拿它跟 `npm` 一节对账 id/版本/能力，**它不上架**）；
   - `pack` 指 `market/pkg/probe-1.0.0.tgz`——生成器对**这枚文件**算 sha256 与字节数，所以索引里那两个数字与用户真到手的东西是同一个对象；
   - `publicUrl` 由生成器校验形状：不是官方 registry、或与 `name`/`version` 拼出来的地址不一致 ⇒ 构建失败。

**几条口径先说清**：镜像前缀**不作用于** npm 条目（换域等于换信任来源，那是另一次裁决）；第三方 registry、私有源、`npm install` 那套依赖解析**都不支持**；包里带的任何脚本我们**没有执行路径**（只按 tar 头取出那一枚清单，其余成员直接跳过）。

## 会被直接拒掉的情形（都是故意的；条数不在标题里写死，写死就会过期）

| 情形 | 为什么 |
| --- | --- |
| 元数据写 1 KB、包实际 90 KB（或反之）| 哈希与字节数由生成器算，作者说了不算——否则"货架写的"和"给你的"可以不是同一件东西 |
| 元数据声明 `ui.widget`、包里其实还带 `serial.send` | **提权必须在货架上就露出来**：能力逐项比对，不一致就构建失败 |
| `publicUrl` 与编译产物名不一致 | 索引不会红，**用户点安装才 404**（N1 就是这么漏的），所以这里先失败 |
| `<目录>/manifest.json` 与同名 `.uartix.json` 并存 | 两份都在，"上架的是哪一份"没人说得清 ⇒ 先删一份 |
| 旁挂文件写 `../x.html` 或绝对路径 | 那就等于允许投稿人把仓库里任意文件灌进上架包。**只许包目录内相对路径**（与 `..` 越界同族红线）|
| 旁挂文件不存在 / 截图文件不存在 | 宁可构建失败，也不上架一个装不开或显示坏图的条目 |
| `npm.name`/`npm.version` 与 `publicUrl` 拼出来的地址不一致 | registry 的地址形状不是手填的：填错不会红在索引上，**用户点安装才 404**（与 `publicUrl` 那条同一个教训）|
| `npm` 那一节写镜像/私有源的域，或 `.tgz` 里根本没有 `package/uartix-plugin.json` | 只放行官方 registry（用户裁决）；那枚清单取不出来就是装不上的包，别指望装的时候才发现 |

（大小没到货架上限也会被契约判掉：包 4 MiB、单图 4 MiB、索引 2 MiB。超限是"这不是货架该给的东西"。）

## 三条你装进来后会看到的行为（不是 bug）

- **默认停用**：带 `logic.run` / `agent.tool` / `serial.send` / `win.control` / `workspace.preset` 这几类能力的包**不属于自动放行集**，要在插件库里手动打开一次才生效。这是 P99a-B 定的红线，市场不例外。
- **一次点击**（安装链接通之后）：确认框一次把来源、字节、哈希前 12 位、要用的能力（中文名）说清；点"安装"就装，不逐条再问。
- **市场不是背书**：索引里有 `verified` 也只表示"这条来自当前索引、过了生成器"，**不代表内容安全**。装自己信得过的来源。

## 想把自己的库接进来

在**「插件市场」那一页顶上那颗齿轮**里（P102 起搬离设置页；设置 → 插件管理 现在只剩本地插件库）：
`市场索引地址`（默认是应用自带那份示例货架，同源、不出网）与 `市场镜像前缀`（默认空，只在直连失败后才试，且它自己的域也要过白名单）。
两行旁边会当场说清**你填的这条会不会被用上**——域不在放行清单里的地址不是"存了就生效"，是打开市场页时照实报错（拉不到时那块还会自己摊开），
应用不会偷偷退回自带那份清单当现状（拉不到就说拉不到，是这套机制的第一条口径）。改完要点那一页的「刷新」才生效。

远程地址的域白名单只有一份：`marketIndex.ts` 里的 `MARKET_ALLOW_HOSTS`（界面、镜像判定、Rust 取回通道都读它）。
