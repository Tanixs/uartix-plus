## 一、修复清单

### ② 空态面板不可点（1 行 CSS，已定案）

**根因**：`theme.css` 的 `.plot-empty { pointer-events: none }` 是历史穿透设计（让点击落到图表）；B1/P65b 在空态加入交互引导（`.spec-guide`）后未恢复命中 → 引导卡的下拉/按钮全部点击穿透失效。

**修复**：
- `.spec-guide { pointer-events: auto; user-select: text; }`——引导卡可点，浮层其余部分保持穿透。
- 已排查 `.plot-empty` 全库 3 处使用点（SpectrumPanel 引导卡 / SpectrumPanel insufficient / Plot2D 提示），仅引导卡含交互元素，修复覆盖完整。

### ③ 部署包控件排版（补缺失 CSS）

**根因**：`OperatorGen.tsx` 使用的 `.set-io-ops` / `.set-switch-inline` 两个类名在 CSS 中**完全无定义**——整行控件靠浏览器默认 inline 流排布：字号继承不一（label ≈12.5px vs input/btn 固定 12px，"字体大小不一"的直接来源）、说明框 `flex:1` 因无 flex 容器而无效、间距与换行不可控。

**修复**：
- theme.css 新增 `.set-io-ops`（flex + wrap + gap 8/10 + margin-top）与 `.set-switch-inline`（inline-flex + 12px + accent 色 checkbox + user-select:none）。
- OperatorGen.tsx 移除 label 上的重复内联样式，由类承载；说明框 `flex:1` 保留（容器有 flex 后生效）。

### ① 频谱无图像（数据层兜底 + 诊断状态机）

**逻辑链路**（触发→传递→回退）：
- 采集链：会话帧流 → Rust parser（tsMs = chunk 级接收时间戳，同块帧共享）→ `appendPoint`（仅数值字段）→ 通道 dataMap；前提 = 频谱/2D/3D 任一面板打开（panelActivity 门控，B1 已修）+ 模板含数值字段 + 会话帧流入 + 已添加通道。
- 计算链：800ms 周期 → `getChanData` → <8 点走 insufficient（有原因）→ `amplitudeSpectrum` → **null 时静默 return（死路）** → HUD 永挂"等待数据…"。
- null 四条路径：n 非幂 / m<2 / **localSpan≤0（chunk 同戳，头号嫌疑）** / 重采样失败。

**修复（A1-A4）**：
- **A1 `plotStore.appendPoint` 保证每通道时间轴严格递增**：同戳/乱序帧强制 `last + 1`（O(1)），根治 chunk 同戳 → localSpan=0 → null 死路；频谱/2D/3D 全链路受益，±1ms 虚拟步长相对采样间隔可忽略。
- **A2 compute 诊断状态机**：调用前 O(1) 预检（只读首末元素），null 时按路径给出结构化失败原因（`FailKind: m2 | span0 | generic`，渲染时 tx() 翻译，语言切换即时生效），不再静默 return。
- **A3 HUD 如实展示**：新增 `.ss-fail`（danger 色）显示"无法计算：<原因>"；"等待数据…"仅在没有失败原因时显示。
- **A4 insufficient 空态升级**：显示实际点数（"该通道当前 N 个点，频谱分析需要至少 8 点"）+ 直达动作按钮（启动/停止演示源 `toggleDemo`、打开 2D 曲线），按钮行 `.plot-empty-ops` 恢复 pointer-events。

**回答"是不是只要打开通道就行"**：不是。需要四条件：①频谱面板在布局中打开 ②模板启用含数值字段 ③会话连接帧流入 ④已添加通道。本批后每一步失败都有明确的界面反馈。

## 三、环境事故与排查记录（重要，供后续会话参考）

本批回归阶段 vitest 全挂（32/32 failed、describe 报 `Cannot read properties of undefined (reading 'config')`），与代码改动无关，排查近 1 小时，最终根因：

1. **Windows 盘符大小写双实例（真根因）**：Bash 工具的 shell shim 以小写 `d:/Projects/...` 作为 cwd 传给 node；ESM 按解析字符串缓存模块，`d:/` 与 `D:/` 会加载两个 vitest 实例 → worker 注入的 runner 与测试文件 import 到的不是同一实例 → runner undefined。**修复 = cd 用大写盘符 `D:/Projects/Larix-Visual-Serial` 再跑 vitest**。以后所有 vitest/vite 命令必须大写盘符起跑。
2. **node_modules 局部损伤（连带）**：@tauri-apps/api 的 `external/tslib/tslib.es6.js` 缺失（多次 npm 操作被超时 SIGTERM 中断的 reify 残留）→ binbus/framecanvas 系 3 个测试套件 suite 级失败。已从官方 tarball（2.11.1）解包覆盖补全。
3. **npm arborist 崩溃**（`Cannot read properties of null (reading 'edgesOut')`，发生在 `#loadPeerSet`）：本机 npm 对该树做 vitest 5↔4 变更时崩溃，`--legacy-peer-deps` 可绕过。
4. **package.json/package-lock 终态**：vitest 保持 5.0.0（官方 latest，本身无问题）、@tauri-apps/api 保持 `^2`（装 2.11.1）、lock 同步了项目 version 0.3.9 与 sourcemap-codec 1.6.0（兼容小升）+ npm 格式化的 libc 字段清理。package.json 相对 HEAD 无 diff。

**教训**：环境报错先验证路径/盘符大小写与包完整性，再怀疑依赖版本；中途被杀的 npm reify 会留下局部损伤，需要按报错逐包补全。
