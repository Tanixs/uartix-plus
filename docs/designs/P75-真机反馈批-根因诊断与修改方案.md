## 一、问题 2：3D 轨迹「横平竖直」——根因与修复方案

### 1.1 根因（代码级实锤）

**根因 A：对齐层「前值填充」导致三分量时刻错位**

`src/features/plot/plotStore.ts:229-256`（`buildAlignedFull`），增量路径 `:336-360` 同构：

```ts
// 三条通道各自独立时间序列，做多路归并；并集时间轴每产生一个新点：
lastV[best] = v;              // ← 只有「当前到达的那条通道」写入真实值
for (let j = 0; j < chans.length; j++) {
  cols[j].push(lastV[j]);     // ← 其余通道写「上一个值」= 前值填充（不是 null）
}
```

后果：点 `(x[i], y[i], z[i])` 中，X 可能是 t=100ms 的真实采样，Y 是 t=95ms 的旧值，Z 是 t=90ms 的旧值。
**每推进一步只有一个坐标轴跳变，另两轴钉住不动** → 相邻两点之间是纯轴对齐位移 → 投影到任意两面都是横线/竖线交替 → 就是截图里那团直角网格。

`plot3dStore.ts:545-546` 的注释本身也承认了这个机制：
```
// 某轴尚无首点（前向填充后仍 null）→ 跳过：3D 不能编造坐标；
```

**根因 B：三轴共用单一 scale，值域差异被放大**

`src/features/plot3d/scene.ts:144-150, 1258-1264`：
```ts
const anchor = [0, 0, 0];
let scale = 1;                                    // ← 单一标量，三轴共用
baseExtent = Math.max(mx[0]-mn[0], mx[1]-mn[1], mx[2]-mn[2], 1e-9);
scale = (VIEW_HALF * 2) / baseExtent;
```
不逐轴归一化。若某轴值域远大于另两轴 → 另两轴被压成近乎常数（呈直线），唯一变化的轴呈阶梯。若某轴恰好恒为常数（`bbMax-bbMin=0`）→ 整个轨迹被压进一个平面，只剩两轴直角折线——最严重形态。

> 用户截图正是「Y 主导 + X/Z 被压扁 + 直角转折」的典型组合。加速度三轴在静止时值域都很小（±几 mg 噪声级别），A1 的台阶效应会被 B 极度放大。

**已排除**：线段几何本身没问题（`scene.ts:238-243` 是连续 `THREE.Line`，非 LineSegments）；32470 点也未触发任何 LOD 阈值（尾窗 12 万、全景 10 万、对齐缓存 4 万均未到）。

### 1.2 修复方案（三层，可分别验收）

**修复 1（核心，必做）｜时间戳最近邻配对，替代前值填充**

在 `plot3dStore` 侧新增「三轴时间戳配对」：不用 `fullAlignedRaw()` 的并集轴，而是取**三轴时间戳的并集**只作为候选时刻，然后对每个时刻用「最近邻（可插值）」取三轴值——**要求三分量的时间差 ≤ 容差**，超出容差则跳过该点。

- 实现位置：`plot3dStore.ts` 的 `pumpOnce()`，`plot3dStore.ts:540-557` 循环内。
- 具体：新增 `buildPairedTriples(colX,colY,colZ,x, tolMs)` 纯函数（可单测）：
  - 对每个候选时刻 `t`，在三轴各自序列里二分找最近邻下标；
  - 若某轴最近邻时间差 `> tolMs` → 该点三轴不齐，跳过（**宁缺毋滥**，而不是编造）；
  - 若 `interp=true` → 在最近邻区间内线性插值（更平滑）。
- 新增设置 `pairTolMs: number`（默认建议 `1.5 × 中位采样间隔`，UI 暴露 3 档：严格/标准/宽松，或直接给毫秒输入）。
- 兼容：`pairMode: "nearest" | "interp" | "off(旧行为)"`，默认 `interp`。

**修复 2（必做）｜逐轴独立归一化**

`scene.ts`：把单标量 `scale` 改成 `scaleVec[3]`，每轴按自身 `extent` 归一化到 `[-VIEW_HALF, VIEW_HALF]`，并保留一个 `uniform` 开关（默认**关闭**逐轴，开启后三轴等比例，保持真实几何比例）：
- 默认 `axisScale: "uniform"`（真实比例，符合工程直觉）；
- 用户在 HUD/右键菜单可切 `"perAxis"`（看清形状，不看真实比例）；
- 网格步长与坐标轴刻度按所选模式标注，**必须在 HUD 明示当前模式**（否则用户会误读比例）。

**修复 3（配套）｜诊断信息可见化**

HUD 增加一行三轴统计（`X: min~max (extent) ...`），让用户一眼看出「是不是某轴是常数/值域极小」——这类问题在 3D 里靠肉眼判断太难。

### 1.3 验收标准

- 接真实 WIT 陀螺仪，缓慢平移/转动传感器 → 轨迹应为**连续平滑曲线**，不再是直角网格；
- 切 `perAxis` 与 `uniform` → 形状与比例变化符合预期，HUD 模式标注同步；
- 三轴时间差超容差的点被跳过 → HUD 显示「已配对 N / 跳过 M」计数；
- 原有测试全绿 + 新增 `buildPairedTriples` 单测（含：三轴等间隔对齐、某轴稀疏、某轴恒定、容差边界、插值正确性）。

## 二、问题 5a：频谱面板空白——根因与修复

### 2.1 根因（实锤）

`src/features/plot/SpectrumPanel.tsx:14-34` 的 import 块**没有 uPlot 基础样式**；而 `src/features/plot/Plot2D.tsx:4` 有：

```ts
import "uplot/dist/uPlot.min.css";
```

全库搜索确认这是唯一一处导入。`node_modules/uplot/dist/uPlot.min.css` 里定义的是 uPlot 画布撑开的**必要条件**：
```css
.uplot { position: relative; width: min-content; }
.u-wrap { position: relative; overflow: hidden; }
.u-over, .u-under { position: absolute; }
.uplot canvas { display: block; position: relative; width: 100%; height: 100%; }
```
缺失后 uPlot 注入的 canvas 没有尺寸规则 → 塌缩为 0 → **面板只剩工具栏与摘要行，图区全空**。与截图 100% 吻合。

`theme.css` 里也没有任何 `.uplot/.u-wrap/.u-under/.u-over` 的兜底规则（只有自定义的 `.u-over .plot-cross-*`），所以确实无补偿。

> 用户上一轮（P74b）反馈「没图」，当时的处理是「升级空态引导卡」——**修错了方向**：引导卡解决的是「不知道该选哪个通道」，不是「没有样式导致画不出来」。这次是真正的根因。

### 2.2 修复方案

**修复 1（必做）**：`SpectrumPanel.tsx` 补 `import "uplot/dist/uPlot.min.css";`
**修复 2（加固）**：把 uPlot 基础样式**提到全局统一导入**（例如在 `main.tsx` 或 `theme.css` 入口 `@import`），并**从 Plot2D 移除局部导入**——避免「每个新 uPlot 面板都要记得导入」这个可再犯路径（这正是本条 bug 的成因）。
**修复 3（防回归）**：新增一条 lint/CI 检查：**任何 `import uPlot from "uplot"` 的文件所在目录，其全局样式链必须含 uPlot CSS**。或者更简单：在 `Plot2D.tsx`/`SpectrumPanel.tsx` 顶部加注释指向统一入口。
**修复 4（易用性）**：`compute()` 的早退分支（`!u` / `!chan` / `!sp` / `<8 点`）目前**静默 return，控制台无任何痕迹**。补 `console.debug` 级日志或摘要行文案（如「点数不足，需要 ≥ N 点」实时显示还需多少点），便于用户自查。

### 2.3 验收标准

- 打开频谱面板 → 选定通道后**立即出现频谱曲线**（FFT 模式）与阶梯柱状（直方图模式）；
- 关闭 2D 曲线面板后只开频谱 → 依然出图（采集门控已确认 `plot2d || spectrum || plot3d` 任一打开即采集，此路无碍）；
- 数据不足时摘要行显示「还差 N 点」而不是「等待数据…」的空泛提示。

## 三、问题 5b：主题色背景 + 灰字按钮——根因与修复

### 3.1 根因（实锤 + 实测对比度）

`src/styles/theme.css:2040-2043`：
```css
.plot-bar .btn.sm { height: 24px; color: var(--text-dim); }   /* ← 无差别覆盖文字色 */
```
而 `src/styles/theme.css:251-255`：
```css
.btn.primary { background: var(--accent); border-color: var(--accent); color: var(--on-accent, #fff); }
```
CSS 特异性：`.plot-bar .btn.sm`（0,2,1）**高于** `.btn.primary`（0,2,0）→ 主题色背景保住了，但文字色被灰字覆盖。

**实测（海棠主题，默认）**：
| 组合 | 对比度 | 判定 |
|---|---|---|
| `--text-dim` #8a6167 on `--accent` #c8445c | **1.11 : 1** | ❌ 几乎不可见 |
| `--on-accent` 正确值为 #fff on #c8445c | 4.73 : 1 | ✅ |

频谱面板的「频谱/直方图/dB/冻结」四个按钮激活态全部踩中——**正是截图 2 那个看不清文字的按钮**。

**衍生问题**：
- **5/8 主题缺 `--on-accent` 定义**（只有 dark/navy/amber 有）→ `.btn.primary` 回退 `#fff`。在 `matcha`(4.04) / `glaze`(3.79) / `amber`(3.17) 等浅色主题上**逼近或低于 3:1 阈值**。
- `Plot3D.tsx:1070,1080` 用 `icon-btn primary`，但**全库没有 `.icon-btn.primary` 规则**（只有 `.plot-bar .icon-btn.primary`，而 Plot3D 的 HUD 不在 `.plot-bar` 内）→ 跟随/校准按钮**激活态无任何视觉反馈**。
- `theme.css:3872,3893` 引用未定义的 `--bg-hover`；`theme.css:4508,6759` 引用未定义的 `--warn-fg` → 静默回退。

### 3.2 修复方案

**修复 1（必做）**：拆分规则，让 primary 不吃灰字：
```css
.plot-bar .btn.sm:not(.primary) { color: var(--text-dim); }
```
或为 `.plot-bar .btn.sm.primary` 显式补 `color: var(--on-accent, #fff)`。**推荐前者**（少一处需同步的覆写）。

**修复 2（必做）**：8 个主题全部补齐 `--on-accent`（light/ocean/matcha/begonia/glaze 5 个缺失），取值按各自 accent 亮度选黑/白：
- begonia #c8445c → `#fff`
- light / ocean / matcha / glaze → 按实测挑选，**保证 `on-accent/accent ≥ 4.5`**（比现有 3.0 阈值更严，因为这是主按钮）。

**修复 3（必做）**：补 `.icon-btn.primary` 全局规则（`background: var(--accent); color: var(--on-accent)`），修掉 Plot3D 跟随/校准按钮的「激活无反馈」。

**修复 4（必做）**：`--bg-hover`、`--warn-fg` 补定义（或在 `theme.css:3872/3893/4508/6759` 改成已存在的令牌）。

**修复 5（防回归，关键）**：升级 `.tools/check-contrast.cjs`
- `--on-accent` 加入**存在性校验**（现在完全没校验 → 漏报 5 个主题）；
- 新增两条组合校验：`--text-dim on --accent`（本次 bug 的形态，必须 ❌ 检出）、`--on-accent on --accent` 阈值从 3.0 提到 **4.5**；
- 新增**「accent 背景必配 color」的静态检查**：扫描全库 `background: var(--accent)` 且同规则无 `color` 的声明，直接 FAIL。这条能拦下整类问题，不只这一处。

**修复 6（同类排查）**：把「选中态/激活态」的控件全扫一遍（chip 胶囊、segmented、tab、开关），确认无其他「主题色底 + 继承灰字」的组合。已知安全：`.orch-top`、`.spec-guide`、`.p3d-cbtn.on`、`.p3d-seg button.on`、`.dv-active-tab`（背景是中性色，accent 只用于 2px 顶条）。

### 3.3 验收标准

- 8 主题 × 所有 primary 按钮：文字清晰可读，`check:theme` 全绿且新增校验项生效；

## 四、问题 3：编排器拖动块「跟拖不动似的」——根因与修复

### 4.1 根因（代码级实锤）

`src/features/orchestrator/OrchestratorPanel.tsx:368-432` 的 `startDrag`：

| 缺陷 | 位置 | 后果 |
|---|---|---|
| **每次 `pointermove` 都 `setDrop()`** | `:397-413`（`onMove`） | `drop` 是面板顶层 state → **每次鼠标移动重渲染整个 OrchestratorPanel 全树**（所有组卡 + 递归块 + 事件槽 + Inspector）。块多/嵌套深时严重掉帧 → 观感就是「拖不动」 |
| **无节流、无 rAF 合并** | `:382-413` | 唯一的 rAF 只用于画布边缘自动滚动，**不用于状态更新** |
| 每 move `getBoundingClientRect()` | `:398` | 读布局 + 立即重渲染 → 强制同步布局（layout thrash）循环 |
| 每 move 递归 `findNode` 全树遍历 | `:401` | O(块数) / 每次鼠标移动 |
| **无 `setPointerCapture`** | 全文件无 | 指针移出窗口/被其他元素截获 → move 事件丢失 |
| **无 `pointercancel` 监听** | 全文件无 | 触摸/滚动/系统手势打断时 `dragRef` 不清、监听器泄漏 → 「突然拖不动」，且下次拖拽叠加监听器 |
| 落点纯几何分割，无阈值/吸附 | `:404` | 上 28%=before、下 28%=after、中间 44% = in 或强制 after → 想插到两行之间却只能追加到行后 = 「不跟手」 |

> 序列器 `SequencerPanel.tsx:341-370` 是同一套模式，但编排器 DOM 子树大得多，所以问题更明显。

### 4.2 修复方案

**修复 1（核心）｜拖拽热点与 React 渲染解耦**
- 拖拽过程**不再走 React state**：落点提示改为**直接操作 DOM**（`classList` 增删）或用一个**独立的拖拽覆盖层组件**（只有它订阅拖拽位置 state）；
- 具体：把 `drop` 从面板顶层 state 移到一个 **`DragOverlay` 叶子组件**（或 `useRef` + 命令式 DOM class），保证 `OrchestratorPanel` 主树**在拖拽期间零重渲染**；
- 参照项目已有范式：控制台 DOM 直写、3D 时间条 10Hz 直写 DOM、`plotUpdate` 的 rAF 阻塞标记。

**修复 2（核心）｜rAF 合并 + 落点计算降本**
- `pointermove` 只记录坐标；实际落点计算与视觉更新**放到 rAF 里每帧最多一次**；
- `getBoundingClientRect` 结果**缓存**（拖拽开始时快照所有 `[data-orch-row]` 的 rect，滚动时用 scrollTop 偏移修正），不在 move 里重新读；
- `findNode` 结果**预建 Map**（拖拽开始时建立 `id → node` 索引），O(1) 查询替代每次递归。

**修复 3（必做）｜指针捕获与中断兜底**
- `pointerdown` 时 `el.setPointerCapture(e.pointerId)`；`pointerup/pointercancel` 时释放；
- **补 `pointercancel` 监听**：与 `pointerup` 走同一收尾路径（清 ref、摘监听、移除提示）；
- 加一个「拖拽看门狗」：若 200ms 内无 move 且指针已抬起（`e.buttons === 0`）→ 自动收尾，防泄漏。

**修复 4（体验）｜真实跟手浮层 + 吸附**
- 新增**跟手 ghost 浮层**（portal 到 body、`position: fixed`、`pointer-events: none`，跟随时直改 `transform: translate3d()` 不走 React state）——这是「拖得动」的核心体感来源；
- 落点判定引入**最近行吸附 + 阈值**：以指针 Y 与各候选行中线的距离取最近；行间空隙明确给 before/after；容器行中间带给 in；
- 边缘自动滚动改为 rAF 内计算（现在每次 move 重启 rAF，逻辑本身可用但需与落点更新合并）。

**修复 5（同步）**：序列器（`SequencerPanel.tsx:341-370`）用同一套拖拽内核 → 抽成共享 hook `useListDrag()`，两处复用，避免再分叉。

### 4.3 验收标准

- 拖拽 20+ 块、含嵌套组的文档：全程 60fps，无卡顿感，ghost 严格跟手；
- 落点提示准确：能明确插到任意两行之间、能拖进容器、能拖到列表末尾；
- 拖拽中途按 Esc / 指针移出窗口 / 触发系统手势 → 拖拽干净结束，无残留提示、无监听器泄漏（连续拖 10 次内存不涨）；
- 边缘自动滚动流畅；序列器拖拽体验同步提升。

## 六、问题 4：扩充「块」体系（对标迷你世界触发器）

### 6.1 迷你世界触发器模型（调研结论）

三大模块 + 七类代码块：

| 类别 | 说明 | 我们的现状 |
|---|---|---|
| **事件** | 触发器起点（玩家/对象/方块/游戏逻辑…） | ✅ 已有 7 种事件块 |
| **条件** | 事件与动作之间的限制（可选） | ✅ `if` + `Cond` |
| **动作** | 执行结果（数量最多） | ⚠️ 只有 8 种，偏少 |
| **取值** | 获取游戏数据（椭圆形，不能独立存在） | ❌ 缺失（我们有 `VarFrom`/`Cond` 但表达力弱） |
| **控制** | 执行逻辑/频率（只跑一次/重复/延迟） | ✅ 有 `loop`/`break`/`abort` |
| **变量** | 数据容器（数值/字符串/布尔，全局/私有） | ✅ 有类型化变量库（缺「私有/局部」概念） |
| **自定义** | 自定义函数（相当于函数） | ✅ 有 `runGroup`（可当子程序） |

**核心借鉴点**：①动作要「多而具体」②取值类要能**嵌套进**条件/动作的输入框 ③重复/延迟是独立控制块 ④触发器可分组、可排序、可整体开关。

### 6.2 新增**动作块**（11 种）

| kind | 名称 | 语义 | 依赖 |
|---|---|---|---|
| `repeat` | **重复执行** | 独立的「重复 N 次 / 每 N ms 重复」控制块（比 `loop` 更贴近触发器心智，且支持「每条事件都重发」） | 现有 loop 内核复用 |
| `delay` | **延迟执行** | `wait` 的触发器化命名（保留 `wait` 作别名，避免老文档失效） | 复用 `wait` |
| `logToTable` | **记录到表格/文件** | 把变量或通道值追加到 CSV / 会话标注——「设备黑匣子」轻量版 | `save_text_file` |
| `snapshot` | **抓取快照** | 冻结当前 2D/3D 视图为图片存盘（复用 `snapshotPng`） | `save_binary_file` |
| `annotate` | **打标注** | 回放/录制时间轴打一个标注点（复用 `sessionStore.annotate`） | session |
| `setChannel` | **写设备参数** | 高阶：把变量值经指定指令工厂协议组帧发出（等价于 `send` + `factory`，但让用户少配一层） | `resolveSend` |
| `sendModbus` | **Modbus 写** | 专为 Modbus 设计：选从站/功能码/地址/值（FC05/06/15/16） | `mb.ts` |
| `pauseSession` | **控制录制** | 开始/停止/保存会话录制 | session |
| `runSuite`(已有) | — | — | — |
| `setWidget` | **控制画布操作** | 设置滑条/开关的值（联动控制画布，形成闭环） | controlsStore |
| `emit` | **触发其他组** | `runGroup` 的「不等待」别名 + 可带参 | 复用 runGroup |

### 6.3 新增**事件块**（5 种）

| kind | 名称 | 语义 |
|---|---|---|
| `frameError` | **解析失败 / 错误率超限** | 复用哨兵错误率检测 |
| `valueChanged` | **通道值改变** | 不只是阈值穿越，任意变化即触发（带 `minDelta` 去抖） |
| `newFrameType` | **出现从未见过的帧型** | 复用哨兵「新帧型」检测——逆向现场神器 |
| `scheduleCron` | **定时（时刻/周期）** | 比 `timer` 更实用：可设「每 5 秒」「每小时整点」等 |
| `manual`(已有) | — | — |

### 6.4 新增**取值 / 变量能力**

- **`Ctx` 取值块**：把「事件字段 / 通道值 / 表达式 / 变量 / 常量」统一成可嵌套的取值来源，让条件与动作的输入端都能直接用一个下拉「取值」选择器（现在 `VarFrom` 已具备雏形，UI 未统一）。
- **局部变量**：为组增加私有变量作用域（现在全是全局），对应迷你世界的「私有变量」。
- **变量分组**：变量库支持按「组」折叠管理（现在是一长条列表）。
- **内置函数库**：`expr.ts` 现在**无任何内置函数**。补一批安全纯函数：`abs/min/max/round/floor/ceil/sqrt/pow/clamp/if(cond,a,b)`——大幅提升条件表达力，且不破坏沙箱（仍无 eval、无 IO）。
