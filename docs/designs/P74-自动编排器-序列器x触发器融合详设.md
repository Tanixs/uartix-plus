# P74 自动编排器（序列器 × 触发器融合）详设

> 状态：待用户确认后执行。
> 需求原文要点：**不覆盖现有测试序列器，复制它另起一个新的**；不要只支持单条「事件-条件-动作」；**保持现有自由拖动与分组**；增加更多可执行块/触发块/事件块；**结合两者，功能更强，不是照抄**。
> 参照系：迷你世界触发器（事件/条件/动作、组与勾选启用、变量库、运行信息流、规则互调）+ 本项目测试序列器（pointer 拖拽排序、组嵌套 ≤4 层、等待帧、帧触发）。

---

## 1. 定位与复制策略

| 项 | 决策 |
|---|---|
| 新面板名 | **自动编排器（Orchestrator）**，面板 id `orchestrator` |
| 代码来源 | `src/features/orchestrator/`，**从 `src/features/sequencer/` 复制起步**（types/store/bind/runner/panel 五件套），再改造 |
| 序列器 | **零改动**，面板保留，两者长期并存 |
| 复用 | `resolveSend` 发送管线（hex/ascii+转义/命令库/指令工厂）、`onFrames` 帧流、`runner.startSuite`、`matchFrame/testFrameMatch`、pointer 拖拽实现、`playAlertTone`/toast |
| 互操作 | 编排器可**一键从序列套件导入**（见 §7）；执行块「运行序列」可调现有套件 |

**一句话模型**：序列器提供了「块流 + 拖动 + 分组」的身体，触发器提供「事件驱动 + 变量 + 逻辑块」的灵魂——每个组既可以像序列一样被手动线性执行，也可以被事件自动唤醒，组与组之间可以互相调用，块体系从 6 种扩到 **19 种**。

## 2. 核心概念模型

```
编排文档 FlowDoc
 ├─ 全局变量库 vars[]（提前声明 + 类型化 + 可持久化，跨组共享）
 └─ 组树（顶层组 ≤32，嵌套 ≤4 层，沿序列器惯例）
     └─ 顶层组 GroupNode = 「编排单元」
         ├─ 事件槽（0..N 个事件块，任一触发 → 整组成为一次运行实例）
         └─ 块流（线性顺序执行，自由拖动排序 / 跨组拖动）
             ├─ 执行块
             ├─ 逻辑块（如果/循环 = 容器块，内嵌子流）
             └─ 嵌套组（组织用；也可被「运行组」当子程序调用）
```

- **组 = 迷你世界的「触发器」**：挂了事件就是自动触发器，没挂事件就是手动/被调用的子程序——两种身份一套模型，不需要用户理解两套东西。
- **块流 = 序列器的步骤流**：组内保持线性顺序、等待/延时语义，这是序列器 validated 的心智，不丢。
- 事件块**只能落在组头事件槽**（拖入块流被拒绝并提示）；块流里不出现事件块——执行语义才成立。

## 3. 块目录（19 种，四大类分色）

### 3.1 事件块（琥珀色，仅落事件槽，7 种）

| 块 | 参数 | 触发语义 |
|---|---|---|
| ▶ 手动 | — | 组卡片/日志里的运行按钮（调试主通道） |
| ⇥ 会话开始/停止 | 方向 | 串口打开/关闭 |
| ⚡ 帧到达 | `match: FrameMatch`（复用：模板/字段/raw 三合一）+ `stride`（每 N 帧取样） | 解码帧流命中；事件上下文注入帧字段 `evt.字段名` |
| 🌡 通道阈值 | `chId`、`above/below`、`value`、`enter/exit`、`持续确认 ms` | 数据侧差分边沿检测（零轮询），穿越去抖后才触发 |
| ⏱ 定时器 | `intervalMs ≥ 100` | 固定间隔（组禁用/总开关关自动停表） |
| 🔔 哨兵告警 | `warn/crit` | `sentinelHub` 新告警 |
| ∆ 变量改变 | `varName` | 引擎内 setVar 后同步触发；上下文注入 `evt.old/evt.new` |

### 3.2 执行块（蓝色，8 种）

| 块 | 参数 | 说明 |
|---|---|---|
| ➤ 发送数据 | `SendPayload`（原样复用：hex/ascii+转义/命令库/指令工厂） | 走 `resolveSend` 同一管线，零分叉 |
| ⏳ 等待 | `ms`（10~60000 钳位） | 组内串行延时（迷你世界「等待五秒」） |
| ◉ 等待帧 | `match` + `timeoutMs` + `忽略失败`开关 | 复用 `waitForFrame`；超时默认中止本组，可改为继续 |
| ▶︎ 运行序列 | `suiteId` + `等待完成` | 调 `runner.startSuite`（序列器不感知） |
| ↻ 运行组 | `groupId` + `等待完成` | 调用任意组为子程序；递归深度保护 |
| ✎ 设置变量 | `varName` ← 常量/通道最新值/表达式/事件字段 | 类型自动收敛，失败留日志 |
| 💬 通知 | `level` + 文本（支持 `${var}` 与 `evt.*` 插值） | toast |
| ♪ 提示音 | `level` | 复用 `playAlertTone` |

### 3.3 逻辑块（紫色容器块，4 种）

| 块 | 参数 | 语义 |
|---|---|---|
| ◇ 如果/否则 | 条件列表（AND）：通道比较/变量比较/表达式/事件字段/会话状态 | 容器块：条件成立跑「那么」子流，否则跑「否则」子流；无否则=跳过 |
| ⟳ 重复循环 | 模式：`次数 N` / `当条件成立`；`间隔 ms`；`上限 1000` | 容器块：迭代子流；while 模式每轮先验条件 |
| ⤶ 跳出循环 | — | 终止最近容器循环 |
| ■ 中止本组 | — | 结束当前运行实例 |

容器嵌套限制：容器套容器 ≤2 层，且总块深度 ≤4（与组嵌套一致）。

## 4. 数据模型（types.ts，JSON 可序列化）

```ts
interface FlowDoc {
  version: 1;
  title: string;
  vars: FlowVar[];            // { name, type: number|string|bool, def, persist }
  groups: GroupNode[];        // 仅顶层组
  settings: { masterOn: boolean };
}

interface GroupNode {
  kind: "group";
  id: string; name: string;
  enabled: boolean; collapsed: boolean;
  events: EventBlock[];       // 事件槽（仅顶层组有语义，嵌套组挂了也只作展示并灰显提示）
  children: FlowNode[];       // 块流
}

type FlowNode = ExecBlock | LogicBlock | GroupNode;

interface BlockBase { id: string; kind: BlockKind; onFail: "abort" | "continue"; }
// ExecBlock 按种类带参数（send/wait/waitFrame/runSuite/runGroup/setVar/toast/sound）
// LogicBlock: { kind:"if", conds: Cond[], then: FlowNode[], else?: FlowNode[] }
//            { kind:"loop", mode:"count"|"while", count?, cond?, intervalMs, cap:1000, body: FlowNode[] }
//            { kind:"break" } { kind:"abort" }
// Cond: { k:"chan"|"var"|"expr"|"evtField"|"session", ... } —— 与序列器 resolveExpected/FrameMatch 对齐
```

- 导入导出：`FlowDoc` JSON round-trip；旧版本缺字段规范化（`onFail` 缺省 abort、`stride` 缺省 1）。
- 持久化：localStorage（沿用序列器键模式，新键 `orchestrator.doc.v1`）。

## 5. 执行引擎（runner 改造，纯 TS 无 React）

### 5.1 实例模型

```
事件 emit ─▶ masterOn ∧ 组启用 ∧ 事件匹配 ─▶ 条件前置检查(事件自带参数)
          ─▶ 入队：组实例 Inst { id, groupId, 栈帧:[{ip, 容器状态}], t0, 触发原因 }
每组 FIFO 队列（上限 8 实例）串行执行；并发策略可选：丢弃新触发(默认)/丢弃旧/终止旧跑新
```

- **栈帧执行**：块流线性走 ip；进入容器块 push 栈帧（如果：先求条件选分支；循环：每轮条件检查+迭代计数+间隔等待）；`break` 弹栈到最近循环、`abort` 清空实例。
- **事件上下文注入**：`evt.*`（帧字段/阈值触值/变量旧新值）在整条块流求值中只读可引用——「帧到达→提取字段→判断→赋值→决策」一气呵成，这是比迷你世界更强的点（它需要变量库绕圈）。

### 5.2 红线（硬保护，全部可测）

| 红线 | 数值 | 落点 |
|---|---|---|
| runGroup 递归深度 | ≤8，超深丢弃+日志 | 引擎 |
| 循环迭代 | 单块 ≤1000；实例累计块执行 ≤10000 | 引擎 |
| 实例总时长 | ≤5min（可配），超时强制中止+日志 | 引擎 |
| send 令牌桶 | 全局 50 个/秒，超限丢弃+日志 | 发送执行器 |
| 全局触发熔断 | 滑动 1s >100 次 → 熔断 1s + toast + 日志标红 | 引擎 |
| 表达式沙箱 | 手写递归下降，无 eval/循环/IO，deadline 50ms（沿 `scriptRunner` deadline 模式） | trigExpr（新） |
| 变量容量 | ≤64 个，字符串值 ≤1KB | store |

### 5.3 运行日志（可解释性）

Ring buffer 800 条：`{ts, instId, groupId, phase: "trigger"|"skip"|"block"|"fail"|"abort", blockId?, detail, durMs}`。
每次触发必留痕（事件原因+参数），每块执行留结果与耗时，条件跳过留原因。UI 虚拟滚动、按组/级别过滤、**点击日志定位并高亮对应块**。

### 5.4 生命周期

- 引擎随 app 惰性挂载：**无启用编排时 emit 直接 return（零开销）**。
- 面板关闭不停止引擎（产品语义：自动化后台运行，总开关管辖；与「面板关闭零开销」红线不冲突——该红线约束面板功能本身）。
- 会话关闭：timer 清表、阈值边沿状态复位、非 persist 变量复位默认值、运行中实例全部中止并留日志。

### 6.1 左栏（编排列表）
- 组树（勾选启用/折叠）、拖拽调整组顺序；右键菜单分组：**编辑**（重命名/复制/从序列导入替换）、**状态**（启用/禁用/清统计）、**视图**（折叠/展开全部）。
- 底部：变量库按钮（抽屉：增删改类型/默认值/持久化开关，≤64）、运行实例徽标。

### 6.2 中栏（画布）——继承序列器拖拽基因
- **组卡片**：头部 = 名称（双击改）+ 事件槽横排徽标（点击编辑、`+` 添加事件）+ `[☑启用][▶手动跑][⋯右键]`。
- **块行**：`⠿` 拖柄 + 类型色条（琥珀/蓝/紫）+ 图标 + **人话摘要**（参数改动即时刷新，如「当 温度>60 进入 → 等2s → 发停机」）+ 上次运行状态点（绿✓/红✗/灰跳过）。运行中当前块描边脉冲高亮。
- **容器块**：头行（条件/次数行内可编辑）+ 缩进子流 + 尾行（否则/结束）；子流同样可拖动排序。
- **拖拽**：沿用序列器 **pointer 拖拽**（Tauri/WebView2 下 HTML5 DnD 不稳的既有结论），ghost 预览 + 目标行上/下/组内高亮 + 画布边缘自动滚动；**事件块非法落点（块流内）红框拒绝 + toast 说明**——不重叠、所见即所得（用户红线）。
- **添加块**：顶栏「+ 添加块」抽屉，三类分栏（事件/执行/逻辑）+ 每块一句话说明；事件类条目标注「将放入事件槽」。

### 6.3 右栏（检查器 + 调试）
- **检查器**：选中块的参数表单——全部下拉/数字输入/通道选择器/命令库选择器，表达式单行 + 实时语法校验（红波浪），每字段带帮助 tooltip，标签左对齐顶对齐（用户偏好），无 emoji（图标用统一线性图标）。
- **变量监视**：500ms 轮询实时值，可手改（改了会触发 varChanged 事件——调试利器）。
- **运行日志**：§5.3，点条目 → 画布定位高亮块。

## 7. 与序列器互操作

- **从序列导入**：`send→发送`、`wait→等待`、`waitForFrame→等待帧`、`assertVar→变量比较条件`（期望值转 Cond）、`note→组备注`、`group→嵌套组`、`SuiteTrigger.onFrame→帧到达事件块`；导入后进入「未启用」状态由用户检查后手动开。
- **运行序列块**：复用 `runner.startSuite`，序列器无感知；序列 HTML 报告能力天然继承。
- 序列器面板、store、JSON 格式**零改动**。

## 8. 测试计划

1. **引擎**：事件路由与总开关；组队列并发三策略；栈帧执行（如果分支/循环计数与 while/间隔/上限/break/abort）；事件上下文注入与只读；递归深度熔断；实例时长中止；send 令牌桶；全局熔断窗口；stride；阈值边沿（enter/exit/抖动去重/持续确认）；varChanged 同步触发。
2. **表达式**：字面量/四则/比较/逻辑/括号/变量表/`evt` 只读/超时/非法语法。
3. **块**：send 参数组装与序列器一致（hex/ascii 转义 golden 用例）；等待帧忽略失败开关；setVar 类型收敛；插值 `${var}`。
4. **导入导出**：FlowDoc round-trip；缺字段规范化；**序列套件→编排转换器**（含 SuiteTrigger 转帧事件）。
5. 回归：tsc / eslint / vitest 全量 / vite build。

## 9. 不做清单（防蔓延）

| 不做 | 理由 |
|---|---|
| 蓝图/节点连线画布 | 三段块流 + 分组是序列器已验证的低门槛形态（用户要求保留拖动分组，不是换范式） |
| OR / 嵌套条件树 | 「如果」块内多条件 AND；OR 用多条组或嵌套如果表达 |
| 条件块内自由编程 | 表达式仅单行纯表达式；复杂逻辑用变量+多块 |
| HTTP/网络/系统命令动作 | 安全红线 |
| 编排 HTML 报告 | 运行日志即审计；报告仍是序列器职责 |
| Operator 包携带编排 | P75 做兼容性验证（参照 P71 plot3d 先例） |
| 变量传参/按设备私有变量 | 共享全局变量表够用；P75 话题 |
| 事件块出现在块流中 | 语义不成立，拖拽层直接拒绝 |

## 11. 真机验收清单

1. **超温保护链**：阈值事件(enter, 持续2s) → setVar ← 通道值 → 如果>50 → 发停机 + 通知；手动顶高通道值验证触发、去抖、冷却。
2. **定时巡检状态机**：定时器 5s → 发查询 → 等待帧(忽略失败) → 变量计数 → tries>3 调用诊断组（runGroup）。
3. **帧驱动**：帧事件 stride=10 + `evt.字段` 在条件/赋值/插值三处生效；200Hz 下 CPU 无感。
4. **循环与熔断**：while 循环 1000 上限熔断；两组互调超过递归 8 被断；日志逐块可解释。
5. **拖拽**：块跨组拖动、容器内拖动、事件块拖入块流被拒；4 层嵌套正常。
6. **从序列导入**：现有套件导入后事件/条件/动作映射正确，序列器原数据未动。
7. **生命周期**：面板关闭规则仍跑；总关即停；重启后 persist 变量恢复、非 persist 复位；断开会话 timer/边沿复位。
