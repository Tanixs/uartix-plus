# P79 虚拟设备网络收发（UDP 对外发射 + 外部命令接收）详设

> 状态：**已实现（P79，2026-09-14）**——按用户追加要求扩展为四链路（UDP / TCP 客户端 / TCP 服务端 / 串口），并完成性能审查。承接 P78c；先例参照 P44 回放桥接。
> 一句话：让虚拟设备像真设备一样**在网络上收发**——仿真帧按 UDP 原样发到指定 host:port（另一台 Uartix+、任何第三方上位机/脚本都能收），并可选监听一个 UDP 端口接收外部命令，走同一套命令匹配器、应答回给发送方。

## 1. 价值与场景

| 场景 | 说明 |
|---|---|
| 双机/多机教学 | A 机启动「温控炉」开 UDP 发射 → B 机用 UDP 服务端接口接入 + 导入同名预设 → 全班无硬件复现同一条曲线。教学关卡（设备 JSON）可分享，接收侧零门槛。 |
| 替身联调 | 用户的下位机固件平时就是「往固定 UDP 端口吐帧 + 收指令」的：用虚拟设备替身，宿主机软件（自研上位机/Node-RED/Python 脚本）不接板子也能全流程调试。 |
| 与时间机器互补 | 回放桥接（P44）对外是 TCP「过去」；vdev 对外是 UDP「现在」，且能收指令闭环——叙事对齐。 |

## 1.5 性能审查结论（用户要求：确认无性能问题）

- **仿真主循环零阻塞**：所有发射路径非阻塞或短超时（UDP 非阻塞 send_to；TCP set_write_timeout 50ms + nodelay；串口 write timeout 50ms）。链路拥塞/对端消失 → 丢帧计数 + lastError，**绝不停摆仿真**；TCP 客户端断线重连每 ≤1s 一次、connect_timeout 80ms。
- **无 net 段 = 零开销**：不建 socket、不起线程，emit 路径仅一次 Option 判断（纳秒级）。
- **线程有界**：每设备最多 1 读线程（udp 监听 / tcp-client 读 / 串口读）或 1 accept + ≤8 客户端读线程（tcp-server）；全部随 FLAG ≤200ms 内退出，vdev_stop 即释放端口。
- **计数走 AtomicU64**，状态查询纯读锁；面板 1s 轮询一次 vdev_status。
- **帧率上限**：periodMs ≥20ms → ≤50Hz，UDP/TCP/串口（115200bps ≈ 14KB/s）均余量充足。
- 实测：cargo test 76/76（含 UDP 回环投递断言「网络字节与 ingest 帧逐字节相同」）。

## 2. 规格扩展（向后兼容）

`VDevSpec` 增加可选 `net` 段；缺省 = 完全维持 P78c 行为（旧设备 JSON 不破）：

```json
"net": {
  "transport": "udp",          // udp | tcp-client | tcp-server | serial（一设备一链路，v1 不做多目标）
  "host": "127.0.0.1", "port": 9010,        // udp 发射目标 / tcp-client 对端 / tcp-server 监听端口
  "bind": "127.0.0.1",                      // tcp-server 监听地址（0.0.0.0=局域网，面板二次确认）
  "listenPort": 9011, "listenBind": "127.0.0.1", // 仅 udp：命令监听（TCP/串口天然双向）
  "path": "COM5", "baud": 115200            // serial
}
```

- `out`：每拍生成的帧除 ingest 本地外，**逐字节相同**地 `send_to(host:port)`。host 可为组播式广播地址（`255.255.255.255` 或 `x.x.x.255` 时自动 `set_broadcast(true)`）。
- `in`：监听 `bind:port`，收到的数据报走**同一 apply_command 匹配器**；命中 → 改输入量 + **应答回给发送方**（不回灌本地管线）；未命中 → 忽略计数。
- 校验：`transport` 仅 `udp`；port 1~65535；`bind` 仅 `127.0.0.1` 或 `0.0.0.0`（后者=显式允许局域网访问，面板需二次确认勾选，帮助注明 Windows 防火墙可能弹窗）；`in.port` 与 `out.port` 不得相同（自环无意义）。
- v2 候选（本批不做）：TCP 客户端发射、多目标分发、串口对（com0com）模拟。

## 3. 架构与状态闭环

### 3.1 数据通路（全部在 vdev.rs 内自持，不碰 net.rs / 接口状态机）

```
tick ─ generate_tick ─┬─ ingest（本地管线：Hex/表格/曲线/录制…）  ← 现状不变
                      └─ out 启用 → udp_out.send_to(host,port)   ← 新增，计数 sent/bytes
in 启用：listener 线程 recv_from(peer) ─ apply_command ─┬─ 命中 → set 输入量 + 应答 send_to(peer) + 日志(matched)
                                                        └─ 未命中 → 日志(ignored)
route_send（本地下发）→ try_send → apply_command ─ 命中 → set + 应答入 pending_replies → 下拍 ingest（现状不变）
```

- **apply_command 重构**：不再把应答塞进 `sim.pending_replies`，改为返回 `Option<Vec<u8>>`；调用方决定去向（本地 → pending_replies → ingest；网络 → send_to(peer)）。纯函数形态保留（P78c 死锁教训：单测绝不持 RUNTIME 锁进 try_send）。
- **监听线程生命周期**：socket 设 200ms 读超时，循环内检查 FLAG；vdev_stop 后 ≤200ms 退出，无泄漏。
- **错误处理**：out 发送失败（ENETUNREACH 等）非致命——计数 + 记录 lastError 供面板展示，仿真继续；in 绑定失败在 **vdev_start 阶段直接 Err**（端口占用等，启动即失败，不留半开状态）。

### 3.2 状态快照

新命令 `vdev_status` → `{ running, device, out: { enabled, target, sent, bytes, lastError? }, in: { enabled, bound, recv, matched, ignored, lastCmd? } }`；面板打开时 1s 轮询；AI 动作 `vdev({op:"status"})` 同步透出。

## 4. 前端

- **vdevStore**：类型 + normalizeSpec 增加 `net`（缺省不写 = 关闭）；校验与 Rust 对齐（双保险）。
- **VdevPanel** 新增「网络（对外收发）」段：out 启用/主机/端口、in 启用/绑定下拉（本机|所有网卡）/端口；`0.0.0.0` 勾选时 confirm 提示「将允许局域网访问」；运行中状态行显示 `→ 已发 N 帧（9010）` `← 收令 M（9011）· 未匹配 K` 与 lastError 红字。
- **内置设备**：温控炉/MPU6050 默认 `net` 关闭，desc 补一句「开 UDP 发射可做双机教学」。
- **接收侧零门槛**：把两台内置设备的帧格式注册为 `＋预设` 条目（「虚拟设备 · 温控炉」/「虚拟 MPU6050（WIT 兼容）」并入现有预设库），B 机一键导入即可解码——当前自动配套模板只在 A 机启动时产生，接收端需要自己的模板。
- **prompts/AI**：VDEV_SPEC 文档补 `net` 字段与示例（「模拟一个向 192.168.1.50:9000 发数据的设备」可直接生成）。
- **帮助**：虚拟设备工坊章节加「网络收发」段（双机教学步骤 + 防火墙提示）。

## 5. 安全与边界

| 项 | 对策 |
|---|---|
| 局域网暴露 | in 默认关闭；bind 默认 127.0.0.1；0.0.0.0 需面板 confirm；文档明示。 |
| 命令注入面 | 外部命令只能改**该设备规格自己声明的输入量**（apply_command 既有白名单语义），无任意写。 |
| 自环 | vdev 与本机 UDP 接口互斥（P78c 已做）：A 机发射口 ≠ B 机接收口的场景才成立；in/out 同端口启动即拒。 |
| 高频发射 | 帧率 = 1000/periodMs（20~5000ms → 0.2~50Hz），UDP 无压力；不做额外限速。 |
| 旧包兼容 | 无 `net` 段的已存设备 JSON / Operator 包不受影响（normalize 缺省关闭）。 |

## 6. 测试

- Rust 单测：net 段解析与校验（端口/bind/同端口拒绝）；apply_command 返回应答的路由语义（本地 vs 网络，纯函数）；127.0.0.1 回环集成冒烟（ephemeral 端口 socket 收发断言，带超时防挂）。
- 前端 vitest：normalizeSpec net 缺省/非法；buildTemplateImport 不受影响。
- 手工：A 机 vdev 发射 → B 机 UDP 服务端接入 + 预设导入 → 曲线一致；B 机控制台发 `HEAT ON`（若 A 开 in）→ A 机曲线响应 + B 机收到 `OK` 应答；vdev_stop 后端口即释放。

## 7. 工作量与拆分

Rust ~140 行（socket 持有/out 发送/监听线程/apply_command 返回值重构/vdev_status/校验/单测）；前端 ~130 行（types+normalize/面板段/状态行/预设注册/prompts/帮助）。一次交付，不分批。

## 7.5 P79-R 追加（已实现）

## 8. 验收清单（真机）

1. 温控炉开 out → 本机另开实例 UDP 服务端收 → 曲线与 A 机一致；
2. 开 in（127.0.0.1）→ 用 Python 脚本发 `HEAT ON` → A 机温度响应 + 脚本收到 `OK\n`；
3. 面板状态行计数走动、lastError 可见；停止设备后端口释放（立刻可重启）；
4. 旧设备（无 net）行为与 P78c 完全一致；
5. bind 0.0.0.0 触发 confirm；in/out 同端口启动被拒且提示原因。
