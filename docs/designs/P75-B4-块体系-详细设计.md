# P75-B4 块体系 · 详细设计

> 状态：**详设待确认**（未动任何代码）
> 定位：P75 方案 B4 项的落地设计——「新增一块要改 8 处文件」的注册表重构 + 11 动作块 + 5 事件块 + expr 函数库 + send 多帧 + 模板库 + 空态引导
> 性能红线不变：引擎零 React/IPC，全部新能力可单测；事件高频路径零稳态分配

---

## 1. 目标与体验基准

对标「迷你世界触发器」的用法模型：**事件（何时）→ 条件（如果）→ 动作（做什么）**，零代码把设备自动化串起来。当前引擎的事件/条件/逻辑骨架已齐，短板在：

1. 动作面太窄（只有发/等/调/写变量/通知 8 种），碰不到控制画布变量、控制页开关、Modbus、图表导出等已有能力；
2. 事件面缺设备侧常见信号（坏帧、通道变化、新帧型、空闲看门狗、组间自定义事件）；
3. 表达式无内置函数（`clamp(abs(a-b)-5, 0, 100)` 写不出来）；
4. send 块发不了多帧协议（WIT 解锁→写入→保存走不通）；
5. 新手上手难：空面板没有任何引导，块语义全靠试。

## 2. 现状：加一个块要改 8 处（登记点剖析）

| # | 文件 | 承担的登记 | 与 kind 的耦合形态 |
|---|------|-----------|------------------|
| 1 | types.ts | `ExecBlock`/`LogicBlock`/`EventBlock` 可辨识联合 + ORCH_LIMITS | TS 联合（不可收敛） |
| 2 | orchestratorStore.ts | `NewBlockKind`/`NewEventKind`、`makeBlock`/`makeEvent`（工厂）、`normalizeNode`/`normalizeEvent`（导入校验+钳位）、序列导入映射 | switch per kind |
| 3 | engine.ts | `execExec`/`execNode`（执行）、`evtMatches`/`mkEvtCtx`/`evtReason`（事件语义） | switch per kind |
| 4 | OrchestratorPanel.tsx | `BLOCK_MENU`(13)/`EVENT_MENU`(7)/`KIND_CLS`/`KIND_LABEL`/`summaryParts` | 手写表 ×3 + switch |
| 5 | OrchestratorInspector.tsx | 参数编辑器分发 | switch per kind |
| 6 | orchestratorBind.ts | 事件源注册（timer/threshold 检测器、needFrames 扫描、deps 实现） | kind 判断散布 |
| 7 | orchAiBuild.ts | `AI_BLOCK_KINDS`(13)/`AI_EVENT_KINDS`(7) + 构造 switch + pendingHints | 手写表 + switch |
| 8 | ai/prompts.ts | 块清单/事件清单/参数说明的文本 | 手写文本（易漂移） |

**真实痛点**：4/7/8 是三份「菜单/清单/说明」的平行宇宙，新块漏登记不报错（7 有 satisfies 守卫但 4/8 没有）；提示文案与 AI 说明天然漂移。

## 3. B4a：BLOCK_REGISTRY 单一注册表（先行，零行为变化）

### 3.1 新文件 `blockRegistry.ts`（纯数据，Node 可测，零 React/IPC）

```ts
import type { NewBlockKind, NewEventKind } from "./orchestratorStore"; // type-only，无运行时环

export interface BlockMeta {
  cat: "exec" | "logic" | "org";          // 菜单分组（原 BlockGrp）
  cls: string;                            // 视觉色类（原 KIND_CLS 值）
  container: boolean;                     // group/if/loop = true（拖拽容器判定，原 buildNodeIndex 逻辑）
  label: { zh: string; en: string };      // 原 KIND_LABEL
  tip: { zh: string; en: string };        // 原 BLOCK_MENU tip
  ai: string;                             // AI 参数说明一行（prompts 自动拼接，消除漂移源）
}
export const BLOCK_REGISTRY: Record<NewBlockKind, BlockMeta> = { /* 13+11 项 */ };

export interface EventMeta {
  label: { zh: string; en: string };
  tip: { zh: string; en: string };
  ai: string;
}
export const EVENT_REGISTRY: Record<NewEventKind, EventMeta> = { /* 7+5 项 */ };
```

**类型守卫**：`Record<NewBlockKind, BlockMeta>` 缺任何一个 kind 直接 tsc 报错——比 orchAiBuild 的 satisfies 更强，登记遗漏在编译期必炸。

### 3.2 工厂迁入

`makeBlock`/`makeEvent` 从 store 迁入 registry（依赖仅 newId + 字面量，无环）；store 侧 `export { makeBlock, makeEvent }` 兼容转发，orchAiBuild/Panel 的 import 不动。

### 3.3 消费方改造（8 登记点 → 3 登记点）

| 消费方 | 改造后 |
|---|---|
| Panel `BLOCK_MENU`/`EVENT_MENU` | **删除**，由 registry 派生（cat 分组、label/tip 直取） |
| Panel `KIND_CLS`/`KIND_LABEL` | **删除**，直取 registry |
| Panel `buildNodeIndex` | container 判定直取 `BLOCK_REGISTRY[n.kind].container` |
| orchAiBuild `AI_BLOCK_KINDS`/`AI_EVENT_KINDS` | 改为 `Object.keys(BLOCK_REGISTRY) as NewBlockKind[]`（守卫由 Record 承担） |
| prompts.ts 块清单文本 | 由 registry 拼接（label + ai 一行说明），消除手写漂移 |
| store `makeBlock/makeEvent` | 迁入 registry，store 转发 |
| engine `execExec`/`evtMatches` 等 | **保留**（执行语义不可表驱动），新增 kind 只在此加 case |
| Inspector 编辑器 switch | **保留**，新增 kind 在此加 case |

**改造后加一个新块 = 4 处**：types 联合 → registry 一行 → engine 执行 case → Inspector 编辑器 case（store normalize 校验 + aiBuild 构造 case 视块而定）。且菜单/AI 清单/prompts 三处**自动生效**。

**依赖方向**（无环）：`types ← registry ← {store(工厂转发), Panel, orchAiBuild, prompts}`；`engine ← bind`；registry 不 import engine/Panel。

**回归**：B4a 落地后 419 测试必须全绿 + 面板菜单/AI 工具清单/提示词输出逐项对照无变化（golden 对拍：改造前后 `Object.keys(BLOCK_REGISTRY)` 与旧 BLOCK_MENU 的 k 序列一致）。

## 4. B4b：expr 内置函数库

**红线修订**：原「无函数调用」改为「**仅白名单纯函数**，无用户可注册函数、无 IO」。解析器加函数调用语法（ident 后跟 `(`），仍受 depth/deadline/nodeCap 三重保护。

```ts
const FUNCS: Record<string, (a: ExprVal[]) => ExprVal> = {
  abs, min, max, round, floor, ceil,            // 数值 1..n 参
  clamp(v, lo, hi),                              // 3 参
  if(cond, a, b),                                // 三元（truthy 选支）
  len(s),                                        // 字符串/evt 长度
  fmt(v, digits),                                // 定点小数字符串（toast/日志插值刚需）
};
```

- 未知函数名/参数个数错误 → ExprError（绝不静默）；
- `if` 为关键字函数（允许短路的只有它：按 truthy 只求值一支）；
- 词法层 `(` 紧跟 ident 且非 `true/false/evt` 才算函数调用，向后兼容零破坏；
- 测试：expr.test.ts 增 ~12 例（白名单/arity 错误/嵌套/deadline/短路）。

## 5. B4c：11 个新动作块

命名对照 P75 草案的修订：`repeat`→并入现有 loop、`delay`→并入现有 wait、`logToTable`→`log`（写引擎日志，表格导出走 exportCsv）、`pauseSession` 砍掉（关闭会话属高危破坏性动作，收益低）。

| # | kind | 菜单 | 参数 | 引擎语义（execExec 新 case） | 依赖（实施时逐一确认 API） |
|---|------|------|------|------------------------------|---------------------------|
| 1 | `setControl` | 写画布变量 | varName、from(VarFrom 复用) | 写控制画布变量（variableStore）；类型收敛失败按 onFail | variableStore 写 API ✅低险 |
| 2 | `setSwitch` | 拨开关 | swId、state(on/off/toggle) | 设置控制页开关状态（controlsStore）；控件不存在按 onFail | controlsStore 状态写 API ✅低险 |
| 3 | `modbusWrite` | Modbus 写 | slaveId、area(coil/reg)、addr、value(ExprVal) | 走现有 Modbus 主站单次写；无主站/超时按 onFail | mb.ts 客户端 API ⚠待确认 |
| 4 | `modbusRead` | Modbus 读 | slaveId、area、addr、count、toVar | 读 N 点 → 首值/数组写入编排变量；失败按 onFail | 同上 ⚠待确认 |
| 5 | `log` | 写日志 | level(info/warn/crit)、text(插值) | 写入引擎运行日志（phase=block），text 走 `${}` 插值；crit 同步 toast | 无 ✅ |
| 6 | `snapshot` | 图表截图 | panelId(plot2d/plot3d/spectrum)、note | 抓取面板 canvas → PNG → 图片库（ai/imageStore 已有容量管理） | imageStore 写 API ⚠待确认；不可行则降级为「存文件 save_text_file 同法走 dialog」 |
| 7 | `exportCsv` | 导出CSV | chanId 或 all、lastN(≤MAX_POINTS) | getChanData → CSV 文本 → save_text_file（Tauri dialog 保存，与部署包同法） | ✅复用现成 IPC |
| 8 | `stopSuite` | 停止序列 | —（无参） | sequencerBind.stopSuite()；未在跑按 ok 并记日志 | ✅API 已存在（bind 内已调用） |
| 9 | `emitFlow` | 发事件 | name(≤32)、data(可选 `k=v` 表达式对 ≤4) | 引擎内派发 `{kind:"flow", name, data}` → 匹配监听 flowEvt 事件的组（跨组解耦通信） | 无 ✅ |
| 10 | `setWidget` | 更新浮球 | widgetId、text(插值) | 更新桌面 widget 文本 | widgetShell ⚠待确认；缺口备选：首期只支持「主浮球文本」，再不行换 `clip`（写剪贴板） |
| 11 | `resetVars` | 复位变量 | scope(all/one)、name(可选) | 复用 engine.sessionStop 的变量复位逻辑（silent，不触发 varChanged 风暴） | 无 ✅ |

**通用约定**：全部走 ExecBase（enabled/note/onFail）；参数钳位规则进 normalizeNode + ORCH_LIMITS 新增常量（如 `flowEvtNameMax=32`、`csvLastNCap=MAX_POINTS`）；引擎日志统一 phase="block" 且 detail 带人话结果；AI 构造（orchAiBuild）支持全部标量参数，容器/引用类（面板 id、变量名下拉）留 UI；pendingHints 补齐（如 modbusWrite 无 slaveId、emitFlow 无 name）。

## 6. B4d：5 个新事件块

| # | kind | 菜单 | 参数 | 数据侧来源（bind） | 事件上下文（mkEvtCtx） |
|---|------|------|------|--------------------|----------------------|
| 1 | `frameError` | 坏帧 | stride(1~10000) | onFrames 中 `valid=false` 的行；复用 frame 的 stride 计数防 200Hz 洪泛 | `len`（帧长） |
| 2 | `chanChanged` | 通道变化 | chId、tol(≥0)、minIntervalMs(50~3600000) | 100ms tick 差分：新事件源表 `chanWatch`（同 timer/threshold 模式 rebuildSources 重建）；节流内丢报 | `chId`/`old`/`new` |
| 3 | `newTpl` | 新帧型 | tplId(空=任意) | onFrames 维护会话级 seenTpl Set（session stop 清空）；首见触发 | `tplId`/`tplName`/`len` |
| 4 | `flowEvt` | 自定义事件 | name | 无需数据源：emitFlow 块/外部 `orchEngine.emit` 直接派发 `{kind:"flow", name, data}` | `name` + data 键值 |
| 5 | `idle` | 会话空闲 | idleMs(1000~3600000) | tick 里对 `lastFrameTs` 差分；触发后置 armed=false，再收帧才重新武装（**电平语义：一次空闲只报一次**） | `idleMs`/`lastTs` |

**引擎侧改动**：`EventBlock`/`FlowEvent` 联合各加 5 个成员；`evtMatches` 加 5 case（flowEvt 按 name 匹配）；`matchGroup` 对带 groupId 的自归属事件（chanChanged/flowEvt/idle）复用「别组不抢」前置判定；`evtReason` 补文案。

**性能预算**（事件高频路径）：
- `needFrames` 扫描扩展：有 frameError/newTpl 事件也置 true（否则维持零分配快路径）；newTpl 的 Set 查询 O(1)、frameError O(1)；
- `chanWatch` 只注册**挂了事件的通道**，tick 内每通道一次尾值读取 + 一次数值比较，无分配；100ms 节拍上限 = 10 次/秒/通道；
- `flowEvt` 纯内存派发，走既有熔断/冷却/队列全部红线；
- 新事件全部可被 stride/节流/冷却抑制，熔断计数口径不变（命中组才计数）。

## 7. B4e：send 多帧 / 模板库 / 空态引导

### 7.1 resolveSend 多帧

- `resolveSend` 返回类型扩展：`{ mode, text } | { mode: "hex"; frames: string[] } | null`；factory 分支 `frames.length !== 1` 的拒绝改为透传全部帧（空帧过滤）；
- 引擎 send 块：多帧按序 `await deps.send` 逐帧发送，**每帧过令牌桶**（50/s 红线按帧计），单帧失败按 onFail；日志 `HEX×3 共 N 字节`；
- 序列器 runner 侧同函数签名兼容（单帧行为零变化，多帧在序列器侧暂不暴露 UI，留 v2）；
- 脚本命令仍不在本批（v2 评估）。

### 7.2 模板库（编排组预设）

- `orchestratorPresets.ts`：内置 4 套（**报警通知**：threshold+toast+sound；**看门狗**：idle+toast+send；**定时轮询**：timer+send+setVar；**收发握手**：frame+send+waitFrame+if），纯数据（GroupNode 字面量 + 说明文案）；
- 入口：空态引导卡「从模板新建」下拉 + 组列表工具条「插入模板」；导入即 addGroup（走 guardLocked，Operator 只读生效）；模板不持久化用户修改（v2 再做用户自定义模板）。

### 7.3 空态引导

- 无组时画布中央引导卡（复用 `.spec-guide` 模式）：三句话说明事件→条件→动作模型 + 「新建组 / 从模板新建 / 让 AI 帮我搭」三个直达（AI = 预填 prompt 的 orchAiBuild 通道）；
- `pointer-events: auto` 只给引导卡（P76②同法，父层保持穿透）。

## 9. 风险与备选

| 风险 | 概率 | 对策 |
|---|---|---|
| modbus/widget/imageStore 的写入 API 与预期不符 | 中 | B4c 开工首日先做 3 个 API 探针（只读确认签名），不符则按 §5 备选降级，不阻塞其余 8 块 |

## 10. 验收清单（真机）

1. 菜单/AI/prompts 与改造前逐字一致（B4a 对拍）；
2. 报警模板一键生成后不改编排即可跑：阈值进→通知+提示音；
3. 看门狗：拔流后 idle 触发一次发看门狗帧，恢复流后重新武装；
4. WIT 多帧协议：send 块一次发 3 帧，令牌桶内不丢；
5. 表达式 `clamp(abs(${evt.value}-set), 0, 100)` 在 toast 插值生效；
6. Operator 只读模式下模板导入/块增删被拒，运行不受影响；
7. 全量回归 419 + 新增 ~67 例全绿；性能：200Hz 满流下编排器面板开着无掉帧。
